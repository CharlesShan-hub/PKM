Object-Based Data Model ^7bY6N0Ef

使用一组表来表示数据及其之间的关系。数据库的结构是由几种类型的固定格式记录构成的。每个表包含特定类型的记录。每种记录类型都定义固定数量的字段或属性。表的列与该记录类型的属性相对应。关系数据模型是最广泛使用的数据模型。 ^d5sZtLL9

实体-关系 (E-R) 数据模型使用一组基本对象（称为实体）以及这些对象之间的关系。实体是现实世界中可区分于其他对象的“事物”或“对象”。 ^TWVRSJDL

半结构化数据模型允许对数据进行规范，其中同一类型的单个数据项可能具有不同的属性集。这与前面提到的数据模型相反，在前面提到的数据模型中，特定类型的每个数据项必须具有相同的属性集。JSON 和可扩展标记语言 (XML) 是广泛使用的半结构化数据表示形式。 ^TSeOJDX6

数据库系统允许将过程存储在数据库中并由数据库系统执行。这可以看作是用封装、方法和对象身份的概念扩展了关系模型。 ^C10e1f9z

Data Abstraction ^hR6WftTt

Physical level -> how ^aEbkmUhL

Logical level -> what ^NKW9cNvz

View level ^RpC3cCPr

最低层次的抽象描述了数据的实际存储方式。物理层详细描述了复杂的低级数据结构。 ^IgwBOb8S

更高一级的抽象描述了数据库中存储的数据，以及这些数据之间存在的关系。因此，逻辑层用少量相对简单的结构来描述整个数据库。虽然在逻辑层实现这些简单结构可能涉及复杂的物理层结构，但逻辑层的使用者无需意识到这种复杂性。这被称为物理数据独立性。 ^LzjtHDaA

许多数据库系统用户并不需要所有这些信息；相反，他们只需要访问数据库的一部分。视图抽象级别的存在是为了简化用户与系统的交互。系统可能会为同一个数据库提供多个视图。 ^7rNmhy5O

Instances and Schemas ^G3mmeqaw

Instances ^EIAXcgf1

特定时刻存储在数据库中的信息集合称为数据库实例。 ^u0SJlfRq

Schemas ^BUkygLFU

数据库的整体设计称为数据库模式。物理模式描述物理级别的数据库设计，而逻辑模式描述逻辑级别的数据库设计。数据库在视图级别也可能有多个模式，有时称为子模式，用于描述数据库的不同视图。 ^gbX3roUQ
