# 第一章（1.2节）总结：ASN.1 基础及规范文件结构

这一节内容明显增多，核心是介绍 **ASN.1 规范文件的实际结构**，而不是 ASN.1 语言本身。

### 1. ASN.1 规范的宏观结构
- 一个完整的 ASN.1 规范通常包含两部分：
  1. **模块定义**（ASN.1 语言的抽象语法定义）
  2. **编码规则说明**（通常是 BER/DER）
- 例外：某些应用规范（如 SNMP）将模块定义和编码说明混在一个文档中

### 2. ASN.1 标准族（X.680 - X.695）
- X.680：基本记号（核心）
- X.681、X.682、X.683：宏、约束、参数化
- X.690、X.691、X.692、X.693、X.694、X.695：各种编码规则（BER、PER、DER、CER、OER、XER、GSER、XML、JSON 等）

### 3. 模块定义的结构
```
<模块名> DEFINITIONS [编码规则默认] [TAGS] [EXTENSIBILITY] ::= BEGIN
    EXPORTS ...
    IMPORTS ...
    -- 类型和值分配 --
END
```
- **DEFINITIONS**：必须的关键字
- **编码规则默认**（可选）：如 `BER`、`PER`，表示默认采用哪种编码，现代常用 `AUTOMATIC TAGS`
- **TAGS**：`EXPLICIT TAGS` / `IMPLICIT TAGS` / `AUTOMATIC TAGS`
- **EXTENSIBILITY**（1994后）：`EXTENSIBILITY IMPLIED` 表示默认所有类型可扩展

### 4. EXPORTS / IMPORTS
- **EXPORTS**：声明该模块对外提供的符号（类型、值、宏）
- **IMPORTS**：从其他模块引用符号，需说明来源模块
- 常用两个环境：`{itu-t(0) ...}` 和 `{iso(1) member-body(2) ...}`
- 1994 前可引用未声明的符号（拖后引用），1994 后不允许

### 5. 模块命名与引用
- 模块名可以很长（如 `MHS-Basic-Access-Unit-1984`）
- 引用外部规范时，用 **ASN.1 点记法**（`{joint-iso-itu-t ...}`）命名模块，而不是文件名

### 6. 编码规范
- 一个完整应用规范 = ASN.1 模块 + 编码规范说明（如“采用本规范的实现应使用 DER 编码”）
- 对同一 ASN.1 定义可以有多种编码规则实现

### 7. 示例：MHS（X.400）规范结构
- 早期大型应用，模块数少（MTS、IPMS、MSP 等）
- 使用 1984/1988 版本，1994 后新增 TS 等模块

### 8. 注意事项
- **模块名不同**不能解决版本兼容问题（不同版本需用不同 OID 标识，而不是改模块名）
- 最新 ASN.1 版本后，规范中大量模块可合并简化
- "real" 关键字用于标识 ASN.1 的“真正”版本

### 9. 总结
- 先看**模块结构**（DEFINITIONS, EXPORTS, IMPORTS）
- 再看**应用协议定义**（顶层类型 = 消息结构）
- ASN.1 标准族已扩展为 16 个标准，涵盖多种编码和扩展机制
