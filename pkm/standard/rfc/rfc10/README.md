# RFC 10 — Documentation Conventions（文档约定·修订版）· Steve Crocker

> **一句话定位**：RFC 3 的**修订版**。三个月后（1969 年 7 月 29 日），NWG 从 5 人扩到 9 人，站点从 4 个扩到 7 个，RAND 和 Lincoln Lab 加入了——于是"宪法"需要更新，连每个人的地址电话都附上了。
>
> 📄 原文见 [rfc10.txt](./rfc10.txt) ｜ 中英对照见 [zh.md](./zh.md)

---

## 〇、背景：三个月，组织膨胀了两倍

对比 RFC 3（4 月）和 RFC 10（7 月），这三个月发生了什么：

| | RFC 3（1969 年 4 月） | RFC 10（1969 年 7 月） |
|---|---|---|
| 成员 | 5 人（Carr、Rulifson、Duvall、Crocker、Deloche） | **9 人**（新增 Shapiro、English-SRI；Haefner-RAND；Rovner、Curry-Lincoln Lab） |
| 机构 | 4 个（Utah/SRI/UCLA/UCSB） | **7 个**（新增 RAND、Lincoln Lab、SDC 进入分发名单） |
| 序号分配 | Bill Duvall（SRI） | **Steve Crocker（UCLA）**——移交了 |
| 分发名单 | 6 人 | **9 人**（新增 Jerry Cole-SDC） |
| 附加内容 | 无 | **9 人完整通讯录（地址+电话）** |

**互联网在长大。** 从一份只有 6 个收件人的手抄笔记，到一份带通讯录的组织章程，只用了 12 周。

## 一、内容细读

### 1. 成员名单（更新版）

> NWG 现在似乎由以下成员组成：Utah 的 Steve Carr、SRI 的 Elmer Shapiro 和 Bill English、UCLA 的 Steve Crocker、RAND 的 John Haefner、Lincoln Lab 的 Paul Rovner 和 Jim Curry。**成员资格不封闭。**

注意：Rulifson 和 Duvall（SRI 的两位）**这次没被列进去**，Shapiro 和 English 上榜了——**1969 年的名单就是这么随意**（SRI 谁有空谁去开会）。但关键句 "Membership is not closed" 一字不差地保留了。

### 2. 内容标准：一字未改

CONTENT 部分**整段照抄 RFC 3**——"及时性优先于打磨"、"最短一句话"、"没有答案的问题也欢迎"。三个月后，Crocker 觉得这套规矩还不用动。**好规矩不需要频繁修订。**

### 3. 格式要求：序号移交 + 规范化

```
1. "Network Working Group" + "Request for Comments:"x
   （x 加下划线；序号现在由 UCLA 的 Steve Crocker 分配）
2. 作者和单位
3. 日期
4. 标题（不需要唯一）
```

两个变化：**序号分配权从 Duvall 移交给了 Crocker**（组织在搬家/换人）；**序号 x 要加下划线**（连排版都规范起来了）。

### 4. 分发名单：9 人

新增了 Jerry Cole（SDC，系统发展公司）。分发机制不变：**作者站点只寄一份，收到的人自己复制。**

### 5. 通讯录：一份 RFC 就是一本人名电话簿

RFC 10 后半部分是大篇幅的 ADDRESSES——**9 个人的完整邮寄地址 + 工作电话 + 秘书电话**：

- Crocker，Boelter Hall 3732 房间，(213) 825-4864
- Kahn，BBN，50 Moulton St.，(617) 491-1850
- Roberts，**五角大楼 3D167 房间**，ODS/ARPA，(202) OX 7-8663
- 等等……

**"Larry Roberts 在五角大楼办公"**——ARPANET 项目经理，一个在五角大楼有办公室、用 OX 开头的首都电话的人，正在用这份 9 人名单调动一个全美网络的建设。1969 年 7 月，距离第一条消息（10 月 29 日）还有 3 个月。

## 二、🔷 本质升华

> - **「人类发明的实现」**：9 人名单、谁分序号、x 加不加下划线、电话是 825-4864 还是 825-2543——全是 1969 年 7 月那个时刻的组织快照。任何细节换一天都可能不同。
> - **「先于人类存在的规律」**：
>   ① **标准自己也要迭代（修订版思想）**：RFC 10 开头第一句就是 "This note is a revision of NWG/RFC #3"——**标准文档和代码一样，有版本号、有修订、有兼容性说明。** 今天你看到的 "This RFC updates RFC X" / HTTP 的 RFC 7230→9110 演进、K8s API 的 v1/v1beta1 版本化，全是同一个动作：**标准是活的东西，必须显式版本化，否则无法演进。**
>   ② **组织扩张的必然产物是"通讯录"**：当协作体从 5 人变 9 人、从同一栋楼变成横跨美国 7 个机构时，**"谁知道谁、怎么找到他"本身就变成了基础设施**。今天这是 LDAP 目录、通讯录系统、Org chart、甚至 GitHub 的成员列表——**协作规模一上来，可发现性（discoverability）就成了刚需**，这不以人的意志为转移。
>   ③ **「共识优先于权威律」的续集**：RFC 10 把格式规范化了（下划线、NIC 编号），但内容标准依然宽松——**形式在收紧、精神在保留**。这提示一条配套规律：**组织成熟化 = 形式制度化 + 核心精神不流失**。制度化掉的都是可固化的流程，保留下来的都是不可固化的原则。
> - **后世重现**：RFC 版本化 → 今天所有标准的 revision/update 机制；通讯录 → 组织目录 / LDAP；序号移交 → 项目维护者交接（bus factor 管理）；"修订版+ 保留原精神" → 宪法修正案与 IEEE 标准的更新流程。RFC 10 是整批文档里最"行政"的一篇，但它证明了：**伟大的协作组织，连行政文书都在认真地写。**

## 三、亮点速览

1. **开头第一句 "This note is a revision of NWG/RFC #3"**——标准版本化思想的最早实例。
2. **成员 5→9、机构 4→7、三个月**——组织扩张的原始档案。
3. **通讯录直接写进 RFC**——"可发现性"作为基础设施的最早体现。
4. **序号分配权移交（Duvall→Crocker）**——维护者交接的 1969 版。
5. **五角大楼办公室 + OX 电话的 Larry Roberts**——项目经理的 1969 年工作状态。

---

## 四、成败与后续

- **成功的**：这套"修订版"机制本身成了 RFC 系列的标配（后来的 RFC 11/12/13 等继续修订细节）；通讯录形式延续到了 RFC 20 之后的各种"名录型"文档；RFC 编号的规范性（下划线、NIC 号）逐步固化。
- **被超越的**：9 人名单三个月后又变了（RFC 11 起又添新人）——**通讯录永远追不上组织扩张，直到后来交给 NIC（网络信息中心）统一维护**。这也解释了为什么 1969 年底出现了专门管理编号和档案的机构。
- **历史彩蛋**：地址里 Larry Roberts 的邮编写的是 "2030l"、Utah 写 "84ll2"——**"l" 代替 "1" 的打字机之魂**再次附体。还有 "One copy only will bve sent"——bve 是 be 的笔误。**修订版宪法自己依然满身错别字。**

## 五、思想传承对照表

| RFC 10 的内容 | 今天的对应物 |
|---|---|
| "This note is a revision of RFC #3" | RFC update/obsoletes 机制、语义化版本号 |
| 成员 5→9、机构 4→7 | 开源社区成长 / 组织扩容 |
| 9 人通讯录写进 RFC | LDAP 目录 / Org Chart / GitHub 成员列表 |
| 序号分配权移交 | 项目维护者交接 / bus factor |
| 内容标准一字未改 | 稳定原则不随流程修改 |
| 下划线 + NIC 编号规范化 | 文档模板 / 排版规范 |
| "Membership is not closed" 保留 | 社区开放性承诺 |
