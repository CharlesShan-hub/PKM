## Redis 事务

### 1. 事务概念

- **批量执行**：Redis 事务通过 `MULTI`、`EXEC`、`DISCARD`、`WATCH` 等命令实现
- **原子性**：事务中的多个命令会被序列化并顺序执行，执行期间不会被其他客户端打断
- **不支持回滚**
    -  即使某个命令失败，比如对字符串+1，后续命令仍会继续执行。
    - 但如果输入了错误的指令然后提交，这个队列都不会执行，看起来像回滚了一样。

| **特性**   | **Redis事务** | **数据库传统事务（如MySQL）** |
| -------- | ----------- | ------------------- |
| **原子性**  | ✅ 执行原子性     | ✅ ACID原子性           |
| **一致性**  | ⚠️ 有限保证     | ✅ 强一致性              |
| **隔离性**  | ✅ 串行化隔离（天然） | 支持多级别隔离             |
| **回滚**   | ❌ **不支持**   | ✅ 支持ROLLBACK        |
| **隔离级别** | 总是串行化       | 可配置（读未提交、读已提交等）     |
| **实现方式** | 命令队列        | 日志（UNDO/REDO）       |
| **锁机制**  | 乐观锁（WATCH）  | 悲观锁（行锁、表锁）          |

### 2. 事务命令

- `MULTI`：标记事务开始
- `EXEC`：执行事务中的所有命令
- `DISCARD`：取消事务
- `WATCH`：监视一个或多个键，如果在事务执行前这些键被修改，则事务被打断
- `UNWATCH`：取消所有 `WATCH` 命令对键的监视

### 3. 事务示例

```
MULTI
SET key1 value1
SET key2 value2
EXEC
```

### 4. 乐观锁

watch某一个内容，如果事务提交前，这个内容被修改了，那这个事务就不会生效
```shell
127.0.0.1:6379> set flag 100
OK
127.0.0.1:6379> watch flag
OK
127.0.0.1:6379> multi
OK
127.0.0.1:6379(TX)> set flag 1
QUEUED
127.0.0.1:6379(TX)> set info "here flag change to 10 in other client"
QUEUED
127.0.0.1:6379(TX)> exec
(nil)
127.0.0.1:6379> get flag
"10"
```

## Redis 发布订阅（AI）

### 1. 发布订阅概念
- Redis 发布订阅是一种消息通信模式，包含发布者和订阅者
- 发布者向频道发送消息，订阅者接收感兴趣频道的消息

### 2. 发布订阅命令
- `PUBLISH channel message`：向指定频道发布消息
- `SUBSCRIBE channel [channel ...]`：订阅一个或多个频道
- `PSUBSCRIBE pattern [pattern ...]`：订阅一个或多个模式匹配的频道
- `UNSUBSCRIBE [channel [channel ...]]`：退订一个或多个频道
- `PUNSUBSCRIBE [pattern [pattern ...]]`：退订一个或多个模式匹配的频道

### 3. 发布订阅示例
```
# 订阅者
SUBSCRIBE news

# 发布者
PUBLISH news "Hello World"
```

### 4. 发布订阅特性
- **无持久化**：消息不会被持久化，订阅者只能接收订阅后发布的消息
- **无确认机制**：发布者不知道消息是否被接收
- **支持模式匹配**：可以使用通配符订阅多个频道

## 缓存穿透（AI）

### 1. 缓存穿透概念
- 缓存穿透是指查询一个不存在的数据，由于缓存中不存在，每次请求都会到达数据库
- 这会导致数据库压力过大，甚至宕机

### 2. 缓存穿透原因
- 业务逻辑不合理，查询不存在的数据
- 恶意攻击，故意查询不存在的数据

### 3. 缓存穿透解决方案
- **缓存空值**：即使查询结果为空，也将其缓存，并设置较短的过期时间
- **布隆过滤器**：使用布隆过滤器判断数据是否存在，如果不存在直接返回
- **接口层校验**：对请求参数进行校验，避免非法请求

## 缓存雪崩（AI）

### 1. 缓存雪崩概念
- 缓存雪崩是指缓存中大量数据同时过期，导致所有请求都到达数据库
- 这会导致数据库压力瞬间增大，甚至宕机

### 2. 缓存雪崩原因
- 缓存数据设置了相同的过期时间
- 缓存服务器宕机

### 3. 缓存雪崩解决方案
- **设置随机过期时间**：为缓存数据设置随机的过期时间，避免同时过期
- **使用缓存集群**：通过缓存集群提高可用性，避免单点故障
- **永不过期策略**：对某些关键数据设置永不过期，通过异步更新保证数据一致性
- **限流降级**：在数据库层面进行限流，避免数据库被压垮

## 缓存击穿（AI）

### 1. 缓存击穿概念
- 缓存击穿是指某个热点数据过期时，大量请求同时到达数据库
- 这会导致数据库压力瞬间增大，甚至宕机

### 2. 缓存击穿原因
- 热点数据过期
- 并发请求量大

### 3. 缓存击穿解决方案
- **设置永不过期**：对热点数据设置永不过期，通过异步更新保证数据一致性
- **加互斥锁**：当缓存失效时，使用互斥锁保证只有一个请求可以访问数据库，其他请求等待
- **缓存预热**：系统启动时加载热点数据到缓存，避免首次访问时击穿
