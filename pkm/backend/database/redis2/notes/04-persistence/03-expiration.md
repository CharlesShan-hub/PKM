# 过期键删除策略

**来源**：《Redis设计与实现》第 9 章

---

## 设置过期时间

| 命令 | 说明 |
|------|------|
| `EXPIRE key seconds` | 设置 key 在 seconds 秒后过期 |
| `PEXPIRE key ms` | 设置 key 在 ms 毫秒后过期 |
| `EXPIREAT key timestamp` | 设置 key 在指定 UNIX 时间戳（秒）过期 |
| `PEXPIREAT key ms_timestamp` | 设置 key 在指定 UNIX 时间戳（毫秒）过期 |

> 所有命令底层最终都是通过 PEXPIREAT 实现的。

## 过期键的存储

每个数据库的 `redisDb` 结构包含一个 `expires` 字典，保存所有键的过期时间：

```c
typedef struct redisDb {
    dict *dict;          // 键空间
    dict *expires;       // 过期字典（键为指针，值为过期时间戳）
    // ...
} redisDb;
```

## 过期键删除策略

### 策略对比

| 策略 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| **定时删除** | 设置过期时间时创建定时器，到期立即删除 | 节约内存 | 消耗 CPU，不现实 |
| **惰性删除** | 每次访问键时检查是否过期，过期就删除 | 节约 CPU | 过期键可能占用内存 |
| **定期删除** | 每隔一段时间检查并删除过期键 | 折中 | — |

### Redis 采用：惰性删除 + 定期删除

#### 惰性删除

在每次执行读写命令之前（如 GET、SET、EXISTS 等），检查输入键是否过期：
- 过期 → 删除键，返回空
- 未过期 → 正常处理

#### 定期删除

由 serverCron 调用 `databasesCron` 函数执行：
1. 从某个数据库的 expires 字典中随机取一部分键检查
2. 删除过期的键
3. 如果过期键比例仍较高，继续抽查
4. 控制每次执行时间，避免阻塞

## AOF、RDB 和复制对过期键的处理

### RDB

| 操作 | 行为 |
|------|------|
| 生成 RDB 文件 | 过期键不会被保存 |
| 载入 RDB 文件 | 主服务器模式：过期键不载入；从服务器模式：全部载入（等待主服务器同步删除） |

### AOF

| 操作 | 行为 |
|------|------|
| 写入 AOF 文件 | 过期键未被删除时正常写入；被删除时追加 DEL 命令 |
| AOF 重写 | 过期键不会被写入重写后的文件 |

### 复制

- **主服务器**：删除过期键后，向所有从服务器发送 DEL 命令
- **从服务器**：不主动删除过期键，等待主服务器的 DEL 命令

> 这保证了主从数据一致性。
