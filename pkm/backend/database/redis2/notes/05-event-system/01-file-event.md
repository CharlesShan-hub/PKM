# 文件事件

**来源**：《Redis设计与实现》第 12 章

---

## 概述

Redis 基于 **Reactor 模式** 开发了自己的网络事件处理器——文件事件处理器。它使用 I/O 多路复用程序来同时监听多个套接字，并根据套接字当前执行的任务关联不同的事件处理器。

文件事件处理器以 **单线程** 方式运行，通过 I/O 多路复用实现高性能网络通信。

## 文件事件处理器的构成

```
┌─────────────┐
│   套接字     │  ← 多个客户端连接
└──────┬──────┘
       ▼
┌─────────────┐
│ I/O多路复用  │  ← select/epoll/kqueue
│    程序      │     将所有产生事件的套接字放入队列
└──────┬──────┘
       ▼
┌─────────────┐
│ 文件事件     │  ← 分派器根据事件类型调用对应处理器
│  分派器      │
└──────┬──────┘
       ▼
┌─────────────┐
│ 事件处理器   │  ← 连接应答/命令请求/命令回复处理器
└─────────────┘
```

## I/O 多路复用程序的实现

Redis 通过包装常见的 I/O 多路复用函数库实现，编译时自动选择系统性能最高的：

```
HAVE_EVPORT  → ae_evport.c  (Solaris)
HAVE_EPOLL   → ae_epoll.c   (Linux)      ← 最常用
HAVE_KQUEUE  → ae_kqueue.c  (macOS/BSD)
default      → ae_select.c  (通用回退)
```

## 事件类型

| 事件类型 | 触发条件 |
|----------|----------|
| `AE_READABLE` | 套接字可读（客户端 write/close），或有新连接（connect） |
| `AE_WRITABLE` | 套接字可写（客户端 read） |

**优先级**：AE_READABLE 优先于 AE_WRITABLE 处理。

## 文件事件处理器

### 1. 连接应答处理器（acceptTcpHandler）

- 负责对连接服务器监听套接字的客户端进行应答
- 初始化时与监听套接字的 AE_READABLE 事件关联

### 2. 命令请求处理器（readQueryFromClient）

- 负责从套接字读入客户端发送的命令请求
- 客户端连接成功后，与客户端套接字的 AE_READABLE 事件关联

### 3. 命令回复处理器（sendReplyToClient）

- 负责将命令回复通过套接字返回给客户端
- 有回复需要发送时，与客户端套接字的 AE_WRITABLE 事件关联
- 回复发送完毕后解除关联

## 一次完整通信过程

1. 客户端连接 → 监听套接字 AE_READABLE → **连接应答处理器** 执行
2. 建立连接，客户端套接字关联 AE_READABLE + **命令请求处理器**
3. 客户端发送命令 → 客户端套接字 AE_READABLE → **命令请求处理器** 读取命令
4. 执行命令，产生回复 → 关联 AE_WRITABLE + **命令回复处理器**
5. 客户端读取回复 → 套接字 AE_WRITABLE → **命令回复处理器** 发送回复，之后解关联
