# SDS — 简单动态字符串

**来源**：《Redis设计与实现》第 2 章

---

## 为什么需要 SDS

C 语言的字符串（以 `\0` 结尾的字符数组）存在以下问题：
1. **获取长度 O(n)** — 需遍历字符串
2. **缓冲区溢出** — strcat 等操作不检查空间
3. **修改字符串需频繁内存重分配**
4. **不能保存二进制数据** — `\0` 被误认为结尾

Redis 构建了 SDS（Simple Dynamic String）来解决这些问题。

## SDS 定义

```c
struct sdshdr {
    int len;        // buf 中已使用字节数（字符串长度）
    int free;       // buf 中未使用字节数
    char buf[];     // 字节数组，保存字符串
};
```

- SDS 遵循 C 字符串以 `\0` 结尾的惯例（兼容部分 C 字符串函数）
- `\0` 不计算在 len 属性中

## SDS 与 C 字符串的区别

| 特性 | C 字符串 | SDS |
|------|----------|-----|
| 获取长度 | O(n) | O(1) — 直接读 len 属性 |
| 缓冲区溢出 | 容易发生 | API 自动检查并扩展空间 |
| 修改字符串 | 必定触发内存重分配 | 空间预分配 + 惰性释放，减少重分配次数 |
| 二进制安全 | 否（`\0` 被当作结尾） | 是（通过 len 判断结束） |
| 兼容 C 函数 | 完全兼容 | 部分兼容（保留 `\0` 结尾） |

## 空间优化策略

### 1. 空间预分配（减少增长时的重分配）

当 SDS 的 API 对 SDS 进行修改并需要扩展空间时，除了分配修改所需的空间外，还会分配额外的未使用空间：

- 修改后 len < 1MB：分配和 len 同样大小的未使用空间（free = len）
- 修改后 len >= 1MB：分配 1MB 的未使用空间

**效果**：将连续增长 N 次所需的内存重分配次数从必定 N 次降低为最多 N 次。

### 2. 惰性空间释放（优化缩短操作）

当 SDS 的 API 需要缩短 SDS 保存的字符串时，不立即释放多出来的字节，而是用 free 属性记录，将来可能再次使用。

同时 SDS 也提供了主动释放未使用空间的 API。

## SDS API 列表

| 函数 | 作用 |
|------|------|
| `sdshdr` | 创建 SDS |
| `sdsfree` | 释放 SDS |
| `sdscat` | 拼接字符串 |
| `sdscpy` | 复制字符串 |
| `sdstrim` | 移除指定字符 |
| `sdslen` | 获取字符串长度 |
| `sdsavail` | 获取未使用空间 |
