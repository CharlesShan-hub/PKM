# URL、URI、URN

---

## URL

一个标准的 URL（统一资源定位符）由多个部分组成，用于精确标识网络上的资源位置。

### URL 的完整格式

```
https://www.example.com:8080/path/to/page
  \___/   \_____________/ \__/ \_________/ 
    |           |          |        |      
  协议      主机名（域名）  端口     路径
```

### 协议

* **什么是协议**：两台计算机之间通信时，需要提前制定好一套数据传送格式。只有提前制定好传送的数据格式，接收方才能根据格式进行解析，拿到数据。这套提前制定好的数据传送格式被称为协议。
* **普通网页协议（未加密）**：​ `http`，例如：`http://`
* **加密的安全网页协议（SSL/TLS）**：`https`，例如：`https://`
* **谁制定的上网协议**：​ **互联网工程任务组（IETF）+ 万维网联盟（W3C）**。
* **对于 HTTP 协议来说包括：**
    - 请求协议：从浏览器向服务器发数据。（B--->S：请求 request）
    - 响应协议：从服务器向浏览器发数据。（S--->B：响应 response）

### 主机名（域名）

* 主机名可以是 `IP 地址`形式，也可以是 `域名`形式。
* **IP 地址**：例如 `9.23.56.78`，用来定位网络中的某台计算机，这台计算机通常被我们称为服务器（**硬件服务器**）。
* **域名**：由于 IP 地址不便于记忆，因此一般会购买一个域名，然后将域名和 IP 地址绑定在一起，用户访问该域名时，DNS 解析器会自动将其解析为 IP 地址。

### 端口号

* 端口号 `port`用来定位计算机上的某个服务（某个软件），对于 BS 结构的系统来说，这个 `port`用来定位的是**硬件服务器**上的 **web 服务器**这个软件。
* **web 服务默认端口**：80
* **Tomcat 服务器默认端口**：8080（Tomcat 是一个具体的 web 服务器软件）

### 路径

* `/path/to/page`，是 web 服务器上的某个资源的路径。
* 例如 `/oa/index.html`表示在 web 服务器中 `oa`这个项目中的 `index.html`页面。


## URL 和 URI 的区别与联系

### 核心区别

| **特性**​ | **URI**​               | **URL**​           |
| ------- | ---------------------- | ------------------ |
| 定位能力​   | **可能不提供资源位置（如 URN）**​  | **必须提供资源访问路径和方式**​ |
| 范围​     | **更广泛（包含 URL 和 URN）**​ | **是 URI 的子集**​     |
| 用途​     | 唯一标识资源​                | 定位并访问资源​           |
### 何时用 URL？

```plain
# 需要定位和访问资源时
- 网页链接：https://www.github.com
- API 端点：https://api.example.com/users
- 文件下载：https://example.com/file.zip
- 图片引用：https://example.com/image.jpg
```

### 何时用 URN？

```plain
# 只需要唯一标识，不关心位置时
- 图书 ISBN：urn:isbn:978-3-16-148410-0
- UUID 标识：urn:uuid:f81d4fae-7dec-11d0-a765-00a0c91e6bf6
- 数字对象标识：urn:doi:10.1000/182
```

### 何时用 URI？

```plain
# 通用标识，可能是 URL 或 URN
- 自定义协议：myapp://user/123
- XML 命名空间：http://www.w3.org/1999/xhtml
- RDF 资源标识：http://example.org/person#john
```

### 类比解释

- **URI 像“身份证号”**：唯一标识一个人，但不告诉你如何找到他。
- **URL 像“家庭住址”**：不仅标识这个人，还告诉你如何去他家（通过街道、门牌号等）。
- **URI = URL + URN**（URL 是 URI 的子集）。
- **URL 必须能定位资源**，URI 只需标识资源（不一定能定位）。
- ❌ 误解1："http:// 开头的就是 URL，其他是 URI"。**正解**：`http://`开头的既是 URL 也是 URI。URL 是 URI 的子集。
- ❌ 误解2："URI 是新的，URL 是旧的"。**正解**：两个概念同时存在，URI 是更广泛的概念。
- ❌ 误解3："Web 开发中只用 URL 就行"。**正解**：在编程中，通常使用 URI 类型，因为它能表示更多情况。
