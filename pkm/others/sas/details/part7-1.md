## 二、核心思想：面向对象的变电站建模

### 传统方式的痛点

传统协议（如 Modbus、DNP3）是这样描述数据的：
```
寄存器 40001 = 220
寄存器 40002 = 221
寄存器 40003 = 222
```

你知道这是电压，但不知道是哪一相、什么品质、什么时候采的。需要查手册、问厂家。

### IEC 61850 的方式

IEC 61850 用**面向对象**的方式描述：
```
MMXU1.PhV.phsA.cVal.mag.f = 220.5
├─┬─┤ ├┬┤ ├┬┤ ├──┬──┤ ├─┬─┤ │
│ │   ││   ││   │    │   │   └─ 值（Value）
│ │   ││   ││   │    │   └────── 浮点数（Float）
│ │   ││   ││   │    └────────── 幅值（Magnitude）
│ │   ││   ││   └──────────────── 复数值（Complex Value）
│ │   ││   └───────────────────── A相（Phase A）
│ │   │└───────────────────────── 相电压（Phase Voltage）
│ │   └────────────────────────── 测量单元 #1
│ └────────────────────────────── 逻辑设备
└──────────────────────────────── IED 名称
```

**关键区别**：数据自带语义，任何符合标准的系统都能理解。

## 三、信息模型的层次结构

Part 7-1 定义了从物理设备到数据属性的完整层次：

```
┌─────────────────────────────────────────────────────────────┐
│  Level 1: 物理设备（Physical Device）                        │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  IED（Intelligent Electronic Device）                  │  │
│  │  智能电子设备，如保护继电器、测控装置                   │  │
│  │  属性：name, type, manufacturer, configVersion         │  │
│  └───────────────────────────────────────────────────────┘  │
│                            │                                │
│  Level 2: 逻辑设备（Logical Device）                         │
│  ┌─────────────────────────▼─────────────────────────────┐  │
│  │  LD（Logical Device）                                  │  │
│  │  功能分区，如 LD0=公用, PROT=保护, CTRL=控制            │  │
│  │  属性：inst（实例名）, desc（描述）                     │  │
│  └───────────────────────────────────────────────────────┘  │
│                            │                                │
│  Level 3: 逻辑节点（Logical Node）                           │
│  ┌─────────────────────────▼─────────────────────────────┐  │
│  │  LN（Logical Node）                                    │  │
│  │  功能实体，如 MMXU=测量, XCBR=断路器, PDIS=距离保护     │  │
│  │  属性：lnClass（类名）, inst（实例号）, prefix（前缀）  │  │
│  └───────────────────────────────────────────────────────┘  │
│                            │                                │
│  Level 4: 数据对象（Data Object）                            │
│  ┌─────────────────────────▼─────────────────────────────┐  │
│  │  DO（Data Object）                                     │  │
│  │  数据集合，如 PhV=相电压, A=电流                        │  │
│  │  属性：name, type（CDC类型）                            │  │
│  └───────────────────────────────────────────────────────┘  │
│                            │                                │
│  Level 5: 数据属性（Data Attribute）                         │
│  ┌─────────────────────────▼─────────────────────────────┐  │
│  │  DA（Data Attribute）                                  │  │
│  │  最小数据单元，如 mag=幅值, q=品质, t=时间戳             │  │
│  │  属性：name, type, fc（功能约束）                       │  │
│  └───────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

## 四、逻辑节点（LN）——功能的标准化

### 什么是逻辑节点？

逻辑节点是 IEC 61850 最核心的创新之一。它把变电站功能**标准化命名**，不同厂家的设备用同一套"词汇"。

### LN 命名规则

```
LN 名称 = [Prefix] + lnClass + [Instance]

示例：
MMXU1      → 测量单元（Measurement）实例1
XCBR1      → 断路器（Circuit Breaker）实例1
PDIS1      → 距离保护（Distance Protection）实例1
PTOC1      → 过流保护（Overcurrent）实例1

带前缀示例：
Line1_XCBR1  → 线路1的断路器
Bus_XCBR1    → 母线的断路器
```

### 常见逻辑节点类

| lnClass | 含义 | 功能 |
|---------|------|------|
| **LLN0** | Logical Node Zero | 每个 LD 的公用节点，包含数据集、报告控制块 |
| **LPHD** | Physical Device | 物理设备信息，如健康状态、代理地址 |
| **MMXU** | Measurement | 三相电气量测量（电压、电流、功率）|
| **MMTR** | Metering | 电能计量（有功、无功电能）|
| **XCBR** | Circuit Breaker | 断路器控制与监测 |
| **XSWI** | Switch | 隔离开关/接地开关控制 |
| **PDIS** | Distance Protection | 距离保护 |
| **PTOC** | Overcurrent | 过流保护 |
| **PDIF** | Differential | 差动保护 |
| **PTRC** | Protection Trip Conditioning | 保护跳闸输出 |
| **CSWI** | Switch Controller | 开关控制器（接收控制命令）|
| **ATCC** | Tap Changer Control | 变压器分接头控制 |
| **TVTR** | Voltage Transformer | 电压互感器 |
| **TCTR** | Current Transformer | 电流互感器 |

**记忆技巧**：
- 第1个字母：功能域（M=测量, X=开关设备, P=保护, C=控制, T=互感器）
- 后3个字母：具体功能

## 五、公共数据类（CDC）——数据结构的标准化

### 什么是 CDC？

CDC（Common Data Class）定义了数据属性的**标准结构**。就像 C 语言里的 `struct`，规定了某个类型的数据必须包含哪些字段。

### 常见 CDC 类型

| CDC | 全称 | 结构 | 用途 |
|-----|------|------|------|
| **SPS** | Single Point Status | stVal, q, t | 单点状态（开关位置）|
| **DPS** | Double Point Status | stVal, q, t | 双点状态（断路器合/分/中间态）|
| **INS** | Integer Status | stVal, q, t | 整数状态（档位、计数）|
| **ACT** | Protection Activation | general, phsA, phsB, phsC, q, t | 保护动作 |
| **MV** | Measured Value | mag, q, t | 测量值（单相）|
| **CMV** | Complex Measured Value | cVal(mag, ang), q, t | 复数测量值（幅值+相角）|
| **WYE** | Wye Connection | phsA, phsB, phsC, neut | 三相星形连接数据 |
| **DEL** | Delta Connection | phsAB, phsBC, phsCA | 三相三角形连接数据 |
| **SPG** | Single Point Setting | setVal, q | 单点设定值 |
| **ING** | Integer Setting | setVal, q, minVal, maxVal | 整数设定值（带范围）|
| **ASG** | Analog Setting | setMag, q, minVal, maxVal | 模拟设定值 |

### CDC 示例：SPS（单点状态）

```
SPS 结构：
├── stVal  (BOOLEAN)  ← 状态值：true/false
├── q      (Quality)  ← 品质：有效/无效/可疑
└── t      (Timestamp)← 时间戳：何时变化

应用：断路器位置
XCBR1.Pos.stVal = true   ← 合位
XCBR1.Pos.q = 0x00       ← 有效
XCBR1.Pos.t = 2024-01-15T10:30:00.123Z
```

### CDC 示例：MV（测量值）

```
MV 结构：
├── mag    (AnalogueValue)  ← 幅值
│   └── f  (FLOAT32)        ← 浮点数值
├── q      (Quality)        ← 品质
└── t      (Timestamp)      ← 时间戳

应用：电压测量
MMXU1.PhV.phsA.mag.f = 220.5  ← 220.5kV
MMXU1.PhV.phsA.q = 0x00       ← 有效
```

## 六、功能约束（FC）——数据的用途分类

FC（Functional Constraint）是对数据属性的**分类标签**，告诉系统这个数据是干什么用的。

| FC | 含义 | 用途 | 示例 |
|----|------|------|------|
| **ST** | Status | 状态信息（只读）| 开关位置、告警状态 |
| **MX** | Measurand | 测量值（只读）| 电压、电流、功率 |
| **SP** | Setpoint | 设定值（可写）| 保护定值、阈值 |
| **SV** | Substitution | 替代值（可写）| 强制置数、调试 |
| **CF** | Configuration | 配置参数（可写）| 通信参数、设备配置 |
| **DC** | Description | 描述信息（只读）| 设备名称、版本信息 |
| **SG** | Setting Group | 定值组（可切换）| 多套保护定值 |
| **SE** | Setting Group Editable | 可编辑定值组 | 在线修改定值 |
| **SR** | Service Response | 服务响应 | 服务调用的返回值 |
| **OR** | Operator Blocking | 操作员闭锁 | 就地/远方切换 |
| **BL** | Blocking | 闭锁 | 功能闭锁状态 |
| **EX** | Extended Definition | 扩展定义 | 厂商扩展 |

**关键理解**：FC 决定了一个数据属性能否被写入。ST/MX 是只读的，SP/CF 是可写的。

## 七、对象引用路径——数据的唯一地址

在 IEC 61850 中，任何数据都有唯一的引用路径：

```
完整引用格式：
[IED名]/[LD实例]/[LN前缀][LN类名][LN实例].[DO名].[DA名]

示例：
IED1/LD0/MMXU1.PhV.phsA.cVal.mag.f
└─┬─┘ └┬┘ └──┬──┘ └─┬─┘ └─┬─┘ └─┬─┘ │
  │    │     │      │     │     │   └─ 浮点数值
  │    │     │      │     │     └───── 幅值
  │    │     │      │     └─────────── 复数值
  │    │     │      └───────────────── A相
  │    │     └──────────────────────── 相电压（DO）
  │    └────────────────────────────── 测量逻辑节点（LN）
  └─────────────────────────────────── 逻辑设备（LD）

带功能约束的引用（用于服务调用）：
IED1/LD0/MMXU1.PhV.phsA.cVal.mag.f[MX]
                                    └─ 功能约束=测量值
```

## 八、与汽车诊断的对比

| 概念 | IEC 61850 | 汽车诊断（UDS）|
|------|-----------|---------------|
| 寻址方式 | 字符串路径（语义化）| 2字节 DID（十六进制）|
| 数据组织 | 面向对象（LN/DO/DA）| 扁平列表（DID/RID）|
| 数据语义 | 自描述（名字即含义）| 需查手册（DID 定义）|
| 数据类型 | CDC 标准结构 | 由 DID 定义，不统一 |
| 功能分类 | FC 功能约束 | 无明确分类 |
| 设备建模 | LN 逻辑节点 | 无标准建模 |

**关键区别**：
- IEC 61850 是**自描述系统**，数据名字就是含义
- UDS 是**查表系统**，必须查 DID 定义才知道是什么

## 九、总结

Part 7-1 的核心思想：

1. **面向对象建模**——把变电站功能抽象成标准化的对象
2. **层次化组织**——IED → LD → LN → DO → DA，层层分解
3. **标准化命名**——LN 类名、CDC 类型统一规范
4. **自描述数据**——数据路径自带语义，无需查手册
5. **功能约束分类**——FC 标签明确数据用途和访问权限

**一句话记忆**：
> Part 7-1 = 面向对象 + 层次结构 + 标准化命名 = 自描述的变电站信息模型
