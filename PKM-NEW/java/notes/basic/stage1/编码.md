## 编码汇总
* ASCII码(American Standard Code for Information Interchange)

  * 大小：1B
  * 格式：最前边的1位统一为0，一共128个字符
  * 内容：英文、数字、标点、特殊控制字符
  * [百度百科ASCII](https://baike.baidu.com/item/ASCII/309296)

* Unicode编码

  * 大小：2B，占用较多存储空间

  * 内容：将世界上所有符号纳入其中，不会出现乱码

  * 最多表示65536个字符（不准确，参考[unicode](https://blog.csdn.net/m0_47841624/article/details/127283939)）

  * Unicode兼容ASCII码：

    | 字符 | Unicode | ASCII    |
    | ---- | ------- | -------- |
    | 'a'  | 0x0061  | 0x61     |
    | '学' | 0x5b66  | 无法表示 |

  * [在Java中如何解决只能存2字节范围内的unicode字符问题](https://zhuanlan.zhihu.com/p/106379925)

* UTF-8编码

  * 大小：1至6字节，变长。字符1字节，汉字3字节。
  * [细说：Unicode, UTF-8, UTF-16, UTF-32, UCS-2, UCS-4](https://www.cnblogs.com/malecrab/p/5300503.html)

* gbk 编码：字母一个字节，汉字两个字节
* gb2312：可以表示汉字，gb2312 < gbk
* big5：繁体

## Java源文件中文乱码问题及解决方案（EditPlus工具）

#### 问题描述

- 现象：Java源文件含中文时，使用EditPlus编写代码后出现中文乱码
- 原因：
    - EditPlus默认使用GBK编码
    - Java 21的javac编译器默认使用UTF-8编码
    - 编码方式不一致导致乱码

#### 解决方案

1. ​**​方案一：编译时指定编码​**​
    
    ```
    javac -encoding GBK 文件名.java
    ```
    
    - 强制编译器使用GBK编码编译
2. ​**​方案二：修改EditPlus编码设置​**​
    
    - 将EditPlus的字符集改为UTF-8
    - 操作路径：设置 → 首选项 → 文件 → 编码

#### 核心原则

所有解决方案的核心都是​**​保持编码方式一致​**​：

- 要么统一为GBK（方案一）
- 要么统一为UTF-8（方案二）

（建议优先采用UTF-8方案，更符合现代开发规范）
